# M7 设置、状态与诊断验收

## 已实现范围

- 系统输入法菜单中的方案、全/半角、简繁、候选横/竖排和系统/浅色/深色主题；所有可点击项均为顶层叶子。
- 设置使用版本化偏好持久化，新 session 自动恢复，已有 session 同步更新。
- 状态变化前先提交当前组合；重新部署前释放所有 session，后台完成后重建。
- 打开用户目录、查看/复制脱敏诊断、恢复默认设置；所有菜单 selector 均由当前 `IMKInputController` 接收并转发。
- 内置词库中的繁简候选和可复现的转换设置。

## 自动化结果

执行：

```bash
./Scripts/test-m7.sh Debug
./Scripts/test-m7.sh Release
```

覆盖：

- 默认值、写入后重建 store 的持久化，以及未知 schema/方向/主题值的安全回退。
- 两个 input engine session 同时获得相同方案与运行时选项。
- 有组合时先提交，再切换设置，已输入文字不会被清空。
- 全拼传统候选“漢字”与启用简体后的“汉字”均由原生 Swift 引擎产生。
- 横排与竖排候选 frame 不重叠、页码区域在边界内。
- 设置和维护菜单项目完整，且没有 InputMethodKit 无法转发的嵌套 action。
- 诊断不包含注入的敏感输入哨兵或完整 Home 路径。
- 恢复默认后回到小鹤双拼（音形辅码）、半角、简体、横排和跟随系统。

M5、M6 Debug 回归同时通过，确认候选视觉基线、五套拼音语料、辅码和用户数据保护未回退。

## 本机人工检查

1. 切换到“风语”，点击菜单栏输入法图标，确认可见“当前：小鹤双拼（音形辅码）”和全部设置项；“输入方案”“候选排列”“候选主题”是分组标题，各选项直接显示在顶层而非子菜单。
2. 逐一点击方案、候选排列和候选主题中的非当前项，确认勾选立即移动；正在输入但尚未选词时切换方案或简繁，确认原组合先正常上屏，没有消失或重复。
3. 在两个不同应用中依次输入，确认方案、全角和简繁设置一致。
4. 将候选排列改为竖排，再输入至少五个候选的编码，确认列表不越过屏幕可见区域且鼠标选词正确。
5. 将主题改为浅色/深色/跟随系统，确认原生玻璃和系统辅助功能降级仍清晰。
6. 选择“重新部署输入引擎”，确认完成提示出现，随后可直接继续输入，不需要注销或重启。
7. 打开脱敏诊断，确认没有刚才输入的文字、候选或完整用户目录。
8. 恢复默认设置，确认用户词典和 `.custom.yaml` 仍保留。

## 预期限制

- 恢复默认只重置风语自己的界面与运行时设置，不删除用户自定义配置或学习词典。
- 正式分发签名、公证和干净机器门禁属于 M9；本机开发安装继续使用 ad-hoc 签名。
