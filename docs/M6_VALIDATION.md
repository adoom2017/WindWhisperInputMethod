# M6 验证记录

## 范围

M6 现交付风语全拼、自然码双拼、小鹤双拼（音形辅码与纯音码）、微软双拼、智能 ABC 双拼、基础词库、用户词频和独立辅码模式。数据来源、许可证、修改和更新方式已记录并锁定。

默认方案固定为“小鹤双拼（音形辅码）”；隔离用户目录首次创建 session 时状态必须为 `flypy` / `小鹤音形`。

## 辅码验收

- 默认小鹤音形严格遵循原始 bin：`ni` 首选“你”，`nir` 首选“倪”，完整码 `nirx` 自动上屏“你”。
- 原小鹤文本码表中的简码直接复用：单键 `k` 包含“可以”，双键 `aj` 包含“按键”，三键 `hvy` 包含“呼之欲出”。
- 原始 bin 的关键一简顺序已验证：`w` 以“我、位”开头，`d` 以“的、打”开头，`u` 以“是、时”开头。
- 兼容词库回填：三简 `ubu` 首选“是不是”，二字词四码 `hdui` 输出“还是”，撞码词 `biru` 按词频首选“比如”并保留单字“俾”。
- 四字词使用最多四键编码。`ahqi` 中主词典“昂起”在前，`sys` 的“爱恨情仇”在后，证明系统补充层不再被错误置顶。
- 小鹤主词典不再生成；测试逐字节核对随包及部署目录中的 `table/prism/reverse` 三个 bin 与 `rime-origin` 摘要一致。
- 词库职责验收：`anui` 由 `top` 的“按时”置顶；`keyi` 主词“可以”在 `user` 的“刻意”之前；`quts` 主词“趋同”在 `full` 的全码字“去”之前。
- `;zuo` 返回 7 个本页候选并包含可见补码注释。
- 补仓颉首码 `k` 后，`;zuok` 缩小为 1 个候选“左”。
- 清空辅码组合后再次输入小鹤 `nihc`，仍返回“你好”，证明纯双拼路径未被辅码规则改写。

## 原配置复用边界

- 直接复用：`rime-origin/build` 中的三个 `flypy` bin，以及 `top/sys/user/full/ok` 文本层；不复用任何 userdb。
- 不再使用 `gaboolic/rime-shuangpin-fuzhuma` 或其他公开词表近似重建主词典。
- 风语运行时不依赖原目录；所需 bin 和文本已复制进应用资源，原目录移动或删除不会影响已安装版本。

## 部署与升级保护

- 桥接层先读取已部署 schema 清单，拒绝切换到不存在的 schema ID。
- 桥接层监听 librime 部署通知；隔离副本中的 `default.yaml` 被故意破坏时返回明确失败，同时保留用户配置。
- 测试在部署前写入带哨兵的 `default.custom.yaml`，两次全量部署后内容完全一致。
- 测试选词触发 `luna_pinyin.userdb` 学习，销毁服务并再次全量部署后 userdb 仍存在。
- 所有测试使用 `/private/tmp` 的隔离目录，不接触正式风语或鼠须管用户数据。
